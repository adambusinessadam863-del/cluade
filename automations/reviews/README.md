# ביקורות ומוניטין

שני חלקים: **בקשות ביקורת בוואטסאפ** (`index.js`) ו**טיוטות תשובה לביקורות** (`drafts.js`, `cli.js`). בדיקות: `node test.js`. הדמיה: `demo.html`.

## עיקרון: לא מסננים
גוגל אוסרת לבקש ביקורת רק מלקוחות מרוצים או להפנות לא-מרוצים לכתוב בפרטי במקום בגוגל. לכן כל לקוח מקבל **אותה הודעה ואותו קישור**. מי שרוצה לשתף משוב פרטי יכול לענות, וזה מועבר לבעל העסק, אבל זה לא מחליף את הקישור. אין הצעת תמורה. ראו `PITCH.md` לפרטים.

## בקשות ביקורת
- ייבוא ביקורים מ-CSV (`שם`, `טלפון`, `ביקור`, `שירות`, `הסכמה`). בלי הסכמה (`כן`) הלקוח מדולג.
- נשלח 3 שעות אחרי הביקור (ניתן לשינוי), לא בלילה ולא בשבת, לא יותר מפעם ב-90 יום ללקוח, ולא אחרי 72 שעות.
- משוב פרטי שחוזר מועבר לבעל העסק בטלגרם, והלקוח מקבל אישור קבלה אחד.
- "הסר" עוצר.

הפעלה: `REVIEW_LINK=https://g.page/r/.../review VISITS_CSV=visits.csv node --env-file=.env index.js` (משתני ה-env כמו ב-`../reminders/.env.example`, בתוספת `REVIEW_LINK`).

**תבנית Meta (`review_request_v1`)**, גוף: `שלום {{1}}, תודה שביקרת ב{{2}} 🙏 נשמח לשמוע איך היה: {{3}}` ובהמשך `אם משהו לא היה כמו שצריך, אפשר פשוט לענות כאן ונטפל בזה אישית.` Meta מחליטה על הקטגוריה.

## טיוטות תשובה
```bash
npm i @anthropic-ai/sdk
export ANTHROPIC_API_KEY=...
node cli.js --reviews samples/reviews.json --profile samples/profile.json --out out
```
מייצר `out/drafts.html`: ביקורת, טיוטה לעריכה עם כפתור העתקה, ודגל "לבדוק" לביקורות שלילית (כוכבים 1–2), איום משפטי, או פרט קשר שלא בפרופיל. בנוסף, סיכום חוזקות ובעיות. **שום דבר לא מתפרסם אוטומטית.**

הדגם `claude-opus-5-5`. הביקורת היא מידע לא אמין: הוראות שכתובות בתוכה (בדוגמה: "התעלם מההוראות הקודמות") אינן מבוצעות. ב-`samples/sample-sheet.html` דוגמת פלט, **שנכתבה ידנית** להמחשת הפורמט.

## מגבלות
- אין חיבור ל-Google Business Profile API. מעתיקים ומדביקים ידנית.
- הדוגמאות ובדיקות הטיוטות הורצו רק מול מודל מדומה. הריצו על ביקורות אמיתיות של הלקוח ובדקו את הסגנון לפני שמוכרים.
