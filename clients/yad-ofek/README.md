# יד אופק הובלות: חבילת הפעלה

כל מה שצריך כדי להפעיל ארבע אוטומציות ללקוח אחד, מאחורי webhook אחד של וואטסאפ.

| קובץ | מה זה |
|---|---|
| `client.json`, `pricing.json`, `flow.js`, `index.js` | הגדרות הלקוח: שם, תבניות, מחירון, תהליך השיחה (כולל שאלת חדרים), הערכת מחיר פנימית |
| `build-quote-site.js` | בונה את כלי ההצעות עם המחירון והמיתוג של הלקוח (`dist/quote`) |
| `deploy/` | Docker, Caddy ו-`.env.example` להפעלה על שרת |
| `INTAKE.md` | שאלון קליטה ללקוח |
| `TEMPLATES.md` | תבניות הודעה להגשה ל-Meta |
| `RUNBOOK.md` | הפעלה שלב אחר שלב, כולל שתי אפשרויות למספר הוואטסאפ |
| `COSTS.md` | מה משלמים, למי ומתי |
| `PROPOSAL.md` | טיוטת הצעה ללקוח |

הקוד המשותף: `../../automations/gateway` (הנתב), `reminders`, `reviews`, `quote`, ו-`../../whatsapp-followup/server` (המענה והמעקב).

## מצב
| חלק | מצב |
|---|---|
| נתב ההודעות וארבע האוטומציות | נבדק: `cd automations/gateway && node test.js` (9 בדיקות מול וואטסאפ מדומה), ונפתח בשרת אמיתי מקומי עם webhook חתום |
| כלי הצעות מחיר ללקוח | נבנה, מחירון **לדוגמה** (לא לשימוש עד שהמחירון האמיתי יוזן) |
| פריסה עם Docker | **לא נבדקה** (אין Docker daemon בסביבה שלי). `docker compose config` עבר |
| חיבור אמיתי ל-Meta או לספק | **לא נעשה**. דורש חשבון, מספר ופרטי התחברות של הלקוח |
| תבניות Meta | נכתבו, **לא הוגשו** |

## מה חסר כדי לצאת לדרך
ראו `RUNBOOK.md`, שלבים 0–3: אישור הלקוח, שאלון ומחירון, החלטה על מספר הוואטסאפ, חשבון Meta, ושרת.
